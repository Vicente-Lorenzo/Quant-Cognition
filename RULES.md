# Quant Trading Framework Project Guidelines

## PROJECT OVERVIEW
A **multi-purpose Quant Trading Framework** built around **cTrader**.
- **Root Folder:** `cAlgo` (in Documents for cTrader compatibility).
- **`Library/` (Python):** Core logic, AI models, trading systems, persistence, Dash frontend.
- **`Sources/` (C#):** cTrader Robots, Indicators, Plugins — bridged to Python via shared memory (named `mmap` + auto-reset Event, single-slot request/response lockstep).
- **`Tests/` (Python):** Pytest suite mirroring `Library/`.
- **`Script/` (Python):** Every script — the boot launcher, the installer and registrar, the Python environment updaters, and one folder per Scheduler workflow (`Setup/` · `Environment/` · `Market/`).
- **`Research/` (Python):** Frozen research method per campaign.

- **Contract terms are a hidden, mutating input to every golden.** `Universe.Contract` holds `SwapLong`/`SwapShort` as *current* broker values, and `UpdatedBy` reads **`Autosave`** — **every cBot run overwrites the row**, so the values a run used are unrecoverable afterwards. It is not just the `SwapPnL` column: sizing is `Risk` at 1% of **balance**, swap feeds balance, so a changed rate moves every volume and every number downstream (runs 1 and 3 prove it — identical trades, different account currency, 59 against 61 distinct volumes). **Pinned since 2026-09-17:** every run writes the terms it used to `Input/Contract.yml` (`ContractAPI.snapshot`), `--contract PATH` replays such a file on `Backtesting`/`Optimization`/`Learning` — in memory only, never saved back to `Universe.Contract`, refusing a file for another contract or with a missing or unknown term — and the Optimization and Learning worker payload carries the parent's terms, so a worker never re-reads a row that may have moved. `RealtimeAPI` rewrites the file whenever the wire's terms change. Each golden folder carries its own `Contract.yml` and `pytest Tests/Golden --golden` pins it, which retired the hand-curated `Tests/Golden/Contract.json`.
- **Never downcast a frame's dtypes.** Until 2026-09-15 `DataframeAPI.frame` ended with `shrink_dtype()`, turning `Float64` into `Float32` and integers into `Int8` on **every database read** and in the preload tape cache. Prices lost digits (`1.08432` → `1.0843199491`), pip sizes lost digits (`1e-05` → `9.99999974737875e-06`), and on USDJPY intra-bar exits moved: removing it brought offline goldens 2 and 4 **16× and 7.6× closer to cTrader** (3.94 → 0.24, 101.63 → 13.34). `Int8` columns also wrap silently under arithmetic. The offline goldens were re-baselined on the corrected engine (`Tests/Golden/RESIDUALS.md`); the tape cache carries `_CACHE_FORMAT_` so a tape written by an older layout is rebuilt, never read. Memory is not a reason to shrink a price.
- **Two engines, two P&L implementations — do not conflate them.** `RealtimeAPI` and `BacktestingAPI` are **siblings** under `SystemAPI` with zero references between them. `Live`/`Simulation`/`Testing` are `RealtimeAPI`, always launched by the Connector cBot when the user presses start in cTrader's Live, Backtesting (non-visual) or Backtesting-visual/Optimization tabs — **never** from the terminal, which is why `--start`/`--stop`/`--account-*`/`--spread-type` do not exist on those subcommands. There `RealtimeAPI` **unpacks `gross_pnl`/`commission_pnl`/`swap_pnl`/`net_pnl` from the wire** (the `_binary_position_`/`_binary_trade_` unpacks) and stores cTrader's numbers verbatim; the contract terms arrive the same way (`SwapLong`/`SwapShort` assigned from the security update), which is the `Autosave` seen in `Universe.Contract`. `Backtesting`/`Optimization`/`Learning` are `BacktestingAPI` and CLI-only, computing their own fills and fees (`truncate(self._commission_(...))` on open, partial close and close). **A `BacktestingAPI` change cannot move the 2026-09-10 goldens, because that code never runs in them.**
- **What the 2026-09-10 goldens actually gate.** Wire decode, portfolio bookkeeping (1024 trades aggregating to 696 deals, deal and trade sums reconciling), the winning/losing and streak classification, and `Library/Statistic` (profit factor and equity drawdown match cTrader). Monetary agreement on gross/commission/swap is **largely tautological** — those values are cTrader's own. Real defects it did find: the `deals.csv` UID export, the balance-drawdown denominator, and the holding-time frame. **cTrader counts the position open at the stop date** — its "Total trades" is our `trades.csv` plus `positions.csv`; `net.csv` reconciles the two and is the table to compare, never `trades.csv` alone. The short-side gap in runs 1-4 (24.11 · -1.30 · 25.65 · 29.54) **equals that position's mark-to-market gap exactly** — cTrader closes it at the final tick of the window and charges its closing commission and full swap, we mark it earlier. Our `truncate(x, 2)` reproduces cTrader's cent quantisation by hand-check (1000 units → 0.045 → 0.04, an 11% effect on run 2) but has **not** been proven in a run.
- **`net.csv` had four defects, all fixed 2026-09-11, all from one place.** `generate_net_report` concatenated the trades and positions frames on `list(set(...).intersection(...))`, which (a) dropped `Position` — absent on `PositionAPI` — so `aggregate_items` returned its input unchanged and **the entire Aggregated half silently became a copy of Individual whenever a position was open** (85 of 85 rows on golden 1); (b) dropped `ExitTimestamp`, so holding time collapsed to `stop - entry` (avg 181.64 days for an H1 year); (c) ordered columns non-deterministically. And `initial_balance` was `account.Balance`, the **closing** balance, so every balance-relative percentage divided by the wrong number — `Max Balance Drawdown (%)` read 44.24 where `absolute / peak balance` gives cTrader's 31.64. The fix is `_aligned_positions_` (open position takes its own `UID` as `Position`, a null `ExitTimestamp`) plus the trades' column order, and `initial_balance` from `equity_curve[0]`. **`calculate_excursion` and `calculate_holding_times` were always correct** — the report path fed them the wrong frame and the wrong balance.
- **`net.csv` reads every equity row from its own column's curve — 2026-09-17.** `PortfolioAPI` keeps three `CurveAPI`s — `EquityCurve` · `BuyEquityCurve` · `SellEquityCurve`, a side being the opening balance plus that side's closed and open P&L, so Buy + Sell − opening balance = Total at every bar. Each records one value and three intrabar points per bar and computes nothing until read: a read mid-session catches up only what is new, and the result is **bit-identical however it was read** (one vectorised pass at the end, random reads, a read every bar — sums use sequential `np.add.accumulate`, never a pairwise sum). Curve rows: Net/Upside/Downside Volatility (per bar and × √bars per year), Max/Mean Equity Drawdown/Runup (intrabar), `Risk-free Rate (%)`, and every ratio twice — Sharpe and Sortino per bar and annualized, Calmar and Sterling over the whole period and annualized, the risk-free rate deducted in every column. Trade rows (returns, winning/losing, trade volatility, balance drawdown, streaks) stay trade-based and follow **realization order** — exit time, never entry time: 676 partial closes share an entry stamp on the DDPG golden, and shuffling those ties moved Max Balance Drawdown from 20.66 % to 26.69 %. `FitnessType` names and values did not move (`SharpeRatio` is still "Sharpe Ratio Annualized"); the constants are `SHARPERATIO` per bar and `SHARPERATIOANN` annualized. `update_data` went from 20.1 to 12.3 µs with two positions open, three curves included, and the report-time catch-up is about 12 ms per curve per 60k bars. `calculate_statistics()` defaults to the recorded window, so the full report is available mid-session.
- **Epoch conversion: two pairs, and they must agree.** `datetime_to_epoch`/`epoch_to_datetime` are pure arithmetic against a naive `EPOCH` and were always timezone-neutral — `BacktestingAPI` uses them, which is why the offline goldens never moved. `datetime_to_timestamp`/`timestamp_to_datetime` used `.timestamp()`/`.fromtimestamp()` and were therefore **local-dependent**, so `RealtimeAPI` stored cTrader's UTC wire stamps as naive **local** time, off by the UTC offset and shifting across DST. Fixed 2026-09-11: the epoch is always read as UTC and a new `zone` argument only decides the label — `None` gives **naive UTC**, a zone gives an aware datetime. `utc_now(zone=None)` is now the single source of "now". **Everything in the framework is naive UTC unless a boundary explicitly asks for a zone.** Do not reintroduce a second convention.
- **Stored stamps are naive UTC too, and cron is the one exception — deliberately.** 2026-09-15: the 32 remaining local `datetime.now()` calls (every `UpdatedAt`, Scheduler `StartedAt`/`StoppedAt`/`Heartbeat`, `Logging.Log`, `Session` timestamps, run-folder names) became `utc_now()`, and `LoggerAPI.stamp` renders UTC so a log line matches the row it describes. **A cron expression still means wall-clock local time** — `0 4 * * *` fires at 04:00 local in both BST and GMT — so `SchedulerAPI._due_`/`_timely_` and the cycle start convert with `utc_to_local` before `croniter` and `local_to_utc` after; `CoordinatorAPI.fits` anchors on `local_now()`. **The repeated hour when clocks go back is handled explicitly:** `_next_` keeps advancing croniter until the UTC candidate is strictly later than the last firing, `_previous_` tries both readings of the hour, `utc_to_local` sets `fold=1` when the round trip disagrees, and `_advance_` never starts a cycle before now — a 01:30 schedule fires once on that night, a sub-hourly one skips the repeated hour. Before this, a `30 1 * * *` workflow in `Europe/London` would have opened a new cycle every tick for a day. Those three helpers live in `Utility/Datetime` and rely on the OS DST rules, so a naive value converts correctly for **its own** date. `Script/Setup/Timezone.py` migrates rows written under the old convention (dry-run by default, `--apply` once, marker under `inspect_persistent("Migrations")`); it deliberately skips `Market.Tick`/`Market.Bar`: their `Timestamp` is broker-side UTC already, and their `UpdatedAt` — stamped local like every other table — is left as it was, because converting a bookkeeping column is not worth a 295 GB rewrite. **The daemon and the executor must be restarted together** — a mixed pair reaps healthy runs or stops reaping stale ones for the offset.
- **Zones are chosen, never assumed — one for display, one per workflow.** 2026-09-16. **Display:** the server always sends UTC; every rendered stamp carries it (`data-utc` on detail spans via `StatusAPI._stamp_`, and `Lightweight.js` marks table cells matching `YYYY-MM-DD HH:MM:SS`), and `App/V2/Assets/Scripts/Zone.js` formats them in the zone picked under Settings → Appearance (`GLOBAL_ZONE_STORAGE_ID`, per device, default **Browser**). Charts follow the same zone — `Lightweight.js` formats the crosshair, axis labels and range dates through `AppZone.epoch` and re-applies them when the zone changes, so a result page never shows two zones (tick marks still sit on UTC boundaries; only their labels move). Zone.js watches text and `data-utc` attribute changes as well as inserted nodes, because React updates a polled detail span in place. Nothing in a payload changes, so old run artifacts render in the chosen zone too; CSV exports, the sheet PNG and a standalone `Plot.html` stay UTC. **Cron:** `Scheduler.Workflow.Zone` (IANA name, empty = this PC's zone) is the zone the workflow's cron is written in — `_due_`, `_timely_` and the cycle start pass it to `utc_to_local`/`local_to_utc`, so `0 9 * * 1-5` in `America/New_York` follows New York's own daylight saving. Member task schedules use their workflow's zone; a standalone scheduled task uses this PC's. `ManagerAPI._zoned_` refuses an unknown name.
- **A suspended daemon must not reap on wake.** 2026-09-16: Windows slept 09:53 → 15:49 UTC, the daemon's first tick found six-hour-old heartbeats and reaped the live Server and Tunnel runs as `Failure` while both kept running. `SchedulerAPI._suspended_` now treats a gap of more than `_interval_ + _LEASE_` between its own ticks as a suspension and defers reaping for one more lease, long enough for every live executor (15 s heartbeat) to beat again. **Latest-row queries order `"StartedAt" DESC NULLS LAST`** — Postgres sorts NULLs first, so two stale NULL-stamped rows made `_suspend_` see a finished run and skip closing the live one.
- **One numeric tolerance: `Utility/Math.EPSILON` = `1e-8`, the default `tolerance` argument of both `equals` and `truncate`.** Unified 2026-09-15 from four values (`EPSILON` 1e-8, `TOLERANCE` 1e-6 in `truncate`, 1e-12 in `equals`, `BacktestingAPI._EPSILON_` 1e-9), measured first: across the five offline goldens, 7 463 `truncate` calls give identical cents at 1e-6, 1e-8, 1e-12 or 0, and 5 412 `equals` calls give identical answers. **The truncation reproduces cTrader's cent quantisation, not the tolerance** (0.045 → 0.04 on golden 2). The tolerance is still a real guard: 1 127 commission values land within 1e-14 of a cent boundary, all from above in these runs, and one from below would lose a cent without it. `equals` is relative with a floor of 1 — `abs(a - b) <= tolerance * max(1, |a|, |b|)`. **Do not change `EPSILON`'s value:** DDPG standardisation adds it to the variance, so it is an input to the thesis model. The SAC actor's own 1e-6 is a paper constant, not a tolerance.
- **Decompose by direction before believing an aggregate.** Twice in one session an aggregate gap read as a per-trade residual and was neither: the gross gap was one open position, and the balance-drawdown gap looked like a partial-close effect until run 4 (which has partial closes) matched. Long/short and absolute/percentage splits both collapsed a hypothesis that a total alone supported.
- **Market data — audited 2026-08-25.** Seven majors (**AUDUSD · EURUSD · GBPUSD · NZDUSD · USDCAD · USDCHF · USDJPY**) carry `D1 · H1 · M1 · MN1` from 2014-01 to 2026-08 (~78k H1 · ~4.6M M1 each); `Market.Tick` = 1,663,014,876 rows · 295 GB — and since 2026-09-17 there is a **second copy**, `Market.TickReload`: the same rows in a TimescaleDB hypertable partitioned by `UID` (31-day chunks, one per security-month), `timestamptz` columns read back as naive UTC, **58 GB** and 7× faster on a bounded day (1274 → 178 ms). It is built and verified (row counts equal, an XOR row hash per chunk) but **nothing reads it yet**: swapping it in means dropping the five `Market.Bar` → `Tick(UID)` foreign keys, because a foreign key pointing into a chunk blocks compression. Rebuild or resume it with `python -m Script.Setup.Reload --apply`. EURJPY and US500 have `Security` rows but no data (1000 defined, 7 populated). **Bars are session-stamped at 22:00 (21:00 DST)** — a Thursday-stamped D1 bar *is* Friday's session, D1 carries 5 bars/week stamped Sun-Thu; an audit against a calendar-day calendar reports every Friday missing, which is convention not loss. **2016-01-11 → 2016-01-25 is absent in all seven pairs, ticks and bars, and is not repairable** — proven 2026-08-25 by a re-download that visited the month and wrote zero rows for those days. Do not spend another download on it; it predates the thesis and is uniform across pairs, so it does not bias comparison.
- **Column order is part of the declaration** — all 12 tables match, in code and physically (2026-08-12). A table whose physical order drifted is out of date even with every column present and correctly typed, so `migrate` rebuilds it. `Market.Tick` was last: 926,936,168 rows · 148 GB · 247 min, row count preserved, five `Bar`→`Tick` foreign keys realigned. `Ask - Mid - Bid` on `Tick` is deliberate, not alphabetical drift.
- **Parameter key order is an input, not formatting.** `DDPGStrategyAPI` builds its observation vector by walking `TechnicalManagement` in dict order, so reordering YAML keys silently permutes a trained model's inputs (one set of weights: +34.02 % · +31.46 % · −46.19 % under three orders). Never write parameters with sorted keys — `write_yaml` and `Parameter._save_` both keep insertion order — and `LadderAPI.pin` keeps a pinned file's order over the defaults it merges in. The durable fix is in (2026-09-17): `DDPGStrategyAPI.save()` writes `Observation.json` beside `DDPG/` and `load()` refuses weights trained under a different layout, naming both orders — legacy weights without the file load with an `Unverified` warning.
- **`--start` and `--stop` are required** on `Backtesting`/`Optimization`/`Learning`; there is no default period. The web Launch form marks both required and refuses to queue without them (`FieldAPI.requirement`, shared with the Scheduler forms).
- **Every run owns a folder, and the CLI mints it.** `Main` takes `--run FOLDER` or mints `<Temp>/Runs/<uid>`: `Run.json` (manifest · command recorded with `join_arguments`, so it splits back into the same arguments · scope · parameter provenance) · `Run.log` · `Input/Parameters.yml` (what actually resolved, so a later override cannot rewrite history — and `--parameters PATH` replays such a file instead of the ladder, merged over `Defaults` without reordering) · `Input/Contract.yml` (the contract terms the run traded under — `--contract PATH` replays it) · `Output/` with `Result.json` · `Export/*.csv` · `Plot.html` · `Weights/`. Bare `--export`/`--plot`/`--profile` resolve into `Output/` via `SystemAPI._destination_`, so the executor passes `--run` and nothing else. **`Result.json` is the data; `Plot.html` is only a viewer** — the web app reads the payload directly, which is what made `--plot` optional again (95% of a 4.9 MB H1 plot was payload).
- **`Run.Retention` decides location, not just pruning.** `Temporary` → `<Temp>/Runs`, `Persistent`/`Favorite` → `<Data>/Runs`; Save and Release move the folder (a rename — same volume) and `ArtifactAPI` resolves either tier. Retention prunes the temporary root by age and **cannot reach** the persisted one — a structural guarantee, which deleted the whole `protected()`/`spared()` mtime-window matcher. Level is changeable only once the run has finished, so nothing relocates a folder a live process is writing.
- **Three log sinks, one owner each.** Console ephemeral (`--console`, Debug) · File is the complete record (`--file`, Debug) writing `Run.log` **inside the run folder**, so run processes never touch the shared rotating entry-point log · Database temporary (`--storage`, Warning default, Debug allowed). The executor captures the child's stdout only to parse progress and catch what bypasses the logger: `_sift_` filters to the storage level but **always keeps lines with no log prefix**, and `_rescue_` appends them to `Run.log`. That is what makes `Run.log` the source of truth — a native crash or a pre-logging argparse failure writes where no Python hook can see it. **`Scheduler.Run.Log` names a file that no longer exists:** `_close_log_` deletes `Console.log` once it has been sifted into `Logging.Log`, and the column is only set at the end, so reading it showed every run "(log unavailable)" and every live run "(no log)" until 2026-09-17. **`ManagerAPI.log(uid)` is the one reader** — the live `Console.log`, then the run folder's `Run.log`, then the stored `Logging.Log` content.
- **The warmup window belongs in the cache key — the tick tape does not.** `BacktestingAPI._preload_` keys on `(security, start, stop, timeframe, auto, resolution, window)`. Omitting `window` let the first candidate's warmup define every later one's (a 30-period baseline ran on a 21-bar warmup; serial disagreed with parallel). Nothing was mutated — `DatasetAPI` is read-only. But keying the *whole* dataset per window was wrong granularity: measured, **0.7%** of a rebuild (bar frames) depends on the window, **99.3%** (the tick tape) does not. `_tape_` caches `_acquire_frames_` on a **window-free** key, so six windows load the tape once. `OptimizationAPI._ordered_` groups candidates by technical parameters to keep the cheap per-window rebuild consecutive (192 EURUSD D1 candidates: 26.96s → 19.09s, scores identical).
- **Do not warm every candidate to the grid's worst-case window.** Self-consistent but breaks standalone reproducibility: on 192 candidates **160 scores changed** (SMA/20 0.4179 → 0.4271) and the top-10 shifted. It also makes a score depend on grid membership.
- **Performance:** `TickAPI` is built and updated once per engine step, so its setters update the existing `PriceAPI`/`TimestampAPI` in place for a plain `float`/`datetime` and fall back to `assign` otherwise (2026-09-16: construction 7.35 → 7.13 µs, three setters 1.05 → 0.94 µs against the pre-refactor tree — the shared `assign` helper alone had doubled the setters). **Datapoint autosave is gone — 2026-09-17.** `DatapointAPI.__setattr__` saved the row on every public attribute assignment when an `autosave=True` InitVar was passed; nothing in the framework ever passed it, yet every datapoint paid one Python call per assignment (19 per `TickAPI`). Removing the hook and caching the `data()` field plan per class and flag set (`DataclassAPI._names_`) measured `TickAPI()` 12.0 → 6.3 µs, `tick.data()` 5.3 → 2.3 µs and `bar.dict(flatten=True)` 46.9 → 24.1 µs, with all 1024 flag-and-class combinations byte-identical and the goldens unmoved. **The `Autosave` in `Universe.Contract.UpdatedBy` is unrelated** — it is `save(by="Autosave")`'s default. Warm NNFX H1 year ≈ 1.5s · D1 10y ≈ 3.2s · H1 10y ≈ 25s; Learning frozen-tape replay ≈ 3.12× per pass; cold preload ~12-15 min per 10y dense-tick window (Parquet cache at `inspect_cached("Preload")`). Measured dead ends, do not retry: numpy ring-buffer for `SeriesAPI`, mypyc/Cython, a drain thread for console/file sinks (a CPU-bound Python thread starves a concurrent writer 253× and the queue fell 93k records behind).
- **Logging performance:** suppressed record 128 ns · emitted 1188 ns · timestamp 234 ns (was 271 / 4961 / 1990). Files in `inspect_temporary("Logs")/<entry-point>.log`, rotated 32 MB × 5, pruned at 30 days.
- **Torch:** 2.13.0+cpu, 24 threads. `Library/__init__.py` preloads `libiomp5md.dll` before MKL and sets `KMP_DUPLICATE_LIB_OK` — **do not delete**. Pin torch in the pip section of `Quant.yml` so `--prune` cannot clobber it.

System toolchain: SDK 10.0.401 and 6.0.100 side by side, no `global.json`, so 10.0.401 is selected for CLI builds.

## OPERATIONAL TRAPS (each of these has cost hours)

- **Learning verbosity:** never run H1/large-bar Learning at `Info`/`Debug` — per-bar log flood costs ~0.6s/bar (a 9h hang for one episode). Use `Warning`; spawn workers too.
- **Logging:** silence via sink levels (`log.console.set_level(...)`), never stdlib `logging.disable()` — the fast path bypasses stdlib. `VerboseLevel` is ordered by **verbosity**, so `Debug` is the largest value and a sink accepts `record <= sink` — the inverse of stdlib.
- **Logger identity comes from the calling frame.** A logger built in `Script/Setup/Market.py` renders `Market - Setup` (the `Library` and `Script` roots are skipped); the same call moved into the shared `Script/Task.py` renders `Task - Script`. Never construct `LoggingAPI()` inside a helper on behalf of a caller — pass the logger in.
- **Console encoding:** `·`/`→` crash cp1252 stdout — use `conda run --no-capture-output` and/or `PYTHONIOENCODING=utf-8`, plus `sys.stdout.reconfigure(encoding="utf-8")` in standalone scripts.
- **`QueryAPI` placeholders:** raw SQL cannot use `::type` casts — `::name::` is the interpolation token. Use `CAST(x AS text)` / `to_char(...)`.
- **A table rebuild is not reversible by hand.** `migrate` renames to a temp, recreates, copies, drops — and a rename **carries inbound foreign keys onto the temp**, so without `realign` the drop either fails or silently strips integrity. A `GENERATED ALWAYS` identity rejects a plain insert, aborting the copy *after* the rename and leaving data in `<Table>_<hex>` — recoverable only if the temp survives. Never let a rebuild drop the temp on an unverified row count.
- **Connection count is a correctness budget, not a tuning knob.** Postgres here is `max_connections` 400. Anything holding connections needs a hard ceiling and a return path — verify with a soak (`pg_stat_activity` must plateau), never by watching a page feel faster. A thread-local cache is not a pool: one grew to 409 clients and was reverted.
- **BLAS in standalone scripts:** calling `np.corrcoef`/LAPACK without importing `Library` first can abort the process (exit 127) — set `KMP_DUPLICATE_LIB_OK=TRUE` or import `Library`.
- **ProcessPool cleanup:** kill worker **children before parents**; orphaned `spawn_main` workers hold ~2 GB each at 0% CPU forever.
- **`psutil` cmdline filters** match your own `python -c "...script.py..."` probe — exclude `os.getpid()`.
- **This repo lives under OneDrive** — `shutil.rmtree(..., ignore_errors=True)` fails silently on sync-locked paths; pass an `onerror` handler and verify with `path.exists()`.
- **Never conclude "no callers" from a truncated search.** A `grep | head` that fills with unrelated matches reads as a clean result and is not one.

## CODING PHILOSOPHY
1. **Precision & Accuracy:** correct, working code over speed.
2. **Simplicity:** do not over-engineer. As simple, concise, readable and performant as possible.
3. **Measure, Don't Guess:** profile before optimizing (`cProfile` by cumulative + tottime, targeted micro-benchmarks). Validate hypotheses with data.
4. **No Environment Configuration:** no `QUANT_*` (or other) environment variables — behavior comes from constructor arguments and CLI flags only.
5. **Generic, never special-cased.** Do not branch on the current context (`if strategy == Download`); keep parallel components symmetric. A special case that solves today's problem is a rule the next component has to know about.
6. **The online backtest is the hot path** — a real strategy, `Transform.Market=True`, the full engine. Optimize against that, not against a synthetic loop; construction machinery is usually the real target.
7. **Readability beats deduplication.** Explicit methods that repeat a few lines — one per named event, like `StrategyAPI`'s position and order update handlers — read better than a closure factory that generates them. Promote shared logic only when it names a real concept, never just to shorten a file. The same holds for dispatch: `SystemAPI._process_updates_` keeps **one `case` per `UpdateID`** rather than grouped patterns over a class table.
8. **Never run a destructive operation against real data while validating.** Create throwaway rows, on a fresh page with no leftover selection, verify the exact target, then clean up and confirm by query that only your rows changed. A live-DB Scheduler UI validation once deleted a real task because an earlier step had left it selected and multi-select made Delete act on it; its run history was unrecoverable.

## CODING STYLE & ORGANIZATION
1. **Language:** **English (US)** spelling (`Optimization`, `behavior`). Exception: identifiers mirroring an external API verbatim (cTrader's `Cancelled`).
2. **General:** No docstrings or comments. Tidy files (no trailing spaces), **one blank line before a `class` definition**, one blank line after `class` and between methods, and **no trailing newline at EOF**. (Exceptions by explicit request: paper-mapping docstrings in `Library/Model/Method/DDPG|SAC|TD3`, `Library/Model/Core/Noise`, `Library/Strategy/Model` and `Library/Strategy/Hybrid/DDPG.py` — kept for the thesis, including the reward-clipping comment in `Strategy/Model/Reward.py`; API-surface docstrings in `Library/Bloomberg`, `Library/Database`, `Library/Logging`. Do not strip these.) **In the docstring-keeping modules only public API methods get one** — private `_methods_` never do; one documented private among undocumented peers reads as noise.
3. **Naming:** `CamelCase` public members; `_naming_` private; `UPPER_SNAKE` public constants; `_UPPER_` private class constants. Lowercase `__post_init__` arguments. Paired verbs are `start`/`stop` (never begin/end or open/close — `LogAPI.start`/`stop`, `CycleAPI.start`); the domain noun is `security`, never `symbol`/`instrument`; private data access is `_fetch_` (read) and `_execute_` (write); every API class carries the `API` suffix.
4. **Typing:** simpler types first in a union — `str | MyClass`, never `MyClass | str`. `Self` from `typing_extensions` for instance returns (3.10 compatibility). `from __future__ import annotations` only when forward references require it — a self-reference, a later class, a `TYPE_CHECKING`-only name, a name the module never imports at all, or a class attribute shadowing a type (`Logging/File.py` has a `Path` property, so `Path | str` inside that class body needs the future import). Prefer built-in types over `typing` classes (`type[X]`, never `Type[X]`).
5. **Imports:** sorted ladder-style block; one blank line between external and project (`Library.*`) imports; explicit imports for internal modules. A call or an import is either **entirely on one line or exactly one name per line** — never fill-style wrapping. Package `__init__.py` re-exports run least to most important (flagship API last) — and anything imported there must also appear in `__all__`. Always import `np`/`pd`/`pl` from `Library.Database.Dataframe`, never directly, so the shared display configuration applies — the only exceptions are `Dataframe.py` and its import closure (`Database.Dataclass`, `Utility.Typing`).
6. **Callbacks:** never reference a component by raw string — pass the `ComponentID`, qualified by the declaring class when the reference crosses a class body (`State(SchedulerBaseAPI.TARGET_STORE_ID, ...)`). Declare each shared identifier **once**, on the lowest common base, and let subclasses bind it in `ids()`. Resolution is by name, so a string works — it just hides typos until runtime.
7. **Density:** dense method bodies without internal blank lines (except complex `__init__`); standard spacing in signatures and assignments.
8. **Architecture:** order methods by category (Connection → Disconnection → Business) then by complexity (simplest first); private before public; fields, properties and methods run least to most important. `@staticmethod` for stateless logic, `InitVar` for temporary inputs. **Generic** helpers live in `Library/Utility` — promote repeated logic there instead of duplicating it — and Utility stays generic: no framework vocabulary (run folders, strategy syntax, market horizons, retention policy beyond a default). The market-data download start is `HORIZON` in `Script/Market/Horizon.py` (2014-01-01). Domain constants and helpers belong on the class that owns the concept (`SystemAPI.OUTPUT`, `SyntaxAPI`, `RangeAPI`). **A base class stays generic too:** `AgentAPI` and `NetworkAPI` assume no algorithm and no layer shapes; shared algorithm machinery goes on an intermediate type (`OffPolicyAgentAPI`).
9. **No path arithmetic.** Never `Path(__file__).parent...` — use `Library/Utility/Path.py` (`traceback_root()` for the repo root, `inspect_module(__file__)` for a module's own folder). The single exception is the `sys.path` bootstrap in a standalone entry point, which by definition runs before `Library` is importable.
10. **Dataframes:** capitalize framework-level columns (`Date`, `Security`). Prefer Polars (`pl`); Pandas (`pd`) for compatibility.
11. **Dataclass class constants carry no annotation.** `_DEPTH_ = 3` is a class attribute; `_DEPTH_: int = 3` is a fourth constructor field. Verify with `fields(Cls)`.
12. **`Structure` merges the parent with `**super().Structure` as the last entry** — one idiom, parent columns after the child's, so the physical order is the declaration order. The exception is a child that redeclares parent columns (`TradeAPI` over `PositionAPI`): there the explicit merge loop keeps the child's declaration and lets the parent only fill the gaps, so it is load-bearing, not drift — replacing it reorders or retypes columns and `migrate` would rebuild the table.
13. **Shared status sets live on the datapoint** (`RunAPI.Busy` · `Live` · `Active` · `Open`), never as private tuples on the consumers that read them.
14. **Explicit over loops for small fixed sets.** One line per named attribute, not a tuple-loop — a reader should see the names, and a typo should be a failure at the line that owns it.
15. **Boolean CLI flags are `store_true`** (present = True, absent = False), never `BooleanOptionalAction`.
16. **Prefer `MISSING` to `None` for "not supplied"** (`from Library.Utility.Typing import MISSING, Missing`; `Missing.__bool__` is False). An optional parameter whose default means "the caller gave nothing" defaults to `MISSING` — `DatabaseAPI` routing params (`database`/`schema`/`table`/`legacy`), `InitVar` resolution inputs, `modal_callbacks(opener, closer)`, `NetworkAPI._uniform_(bound)`, `DatabaseAPI.update(parameters)`. Keep `None` only where it is a real value: **persisted datapoint fields** (`= None`, NULL in the table), a value forwarded to an API that gives `None` a meaning (`seed` to numpy/torch, `timeout` to `Event.wait`), or a default handed back to the caller (`Parameter.first(default=None)`).
17. **No module-level functions or variables unless strictly necessary.** A helper that belongs to a class is a static or class method on it (`DatabaseAPI.primary`, `EnumerationAPI.names()`, `ComponentAPI.tip`, `CatalogAPI.resolve`); a callback factory lives in `App/V2/Core/Callback.py` (`modal_callbacks`) or on its page class (`LaunchAPI.launch_callbacks`, `SchedulerEntityAPI.entity_callbacks`). The standing exceptions are pure function modules (the `Utility` helpers, `Statistic/Metric`, `Portfolio/Sizing`, `System/Selection`), constant modules (`Statistic/Label`), decorators applied inside class bodies (`App/V2/Core/Callback.py`'s callback decorators, `Database/Dataclass.overridefield`), `Dataclass.coerce` — called eleven times per `TickAPI`, where a class lookup measured +125 ns — and `Setup`/`Script` entry points. A module's `if __name__ == "__main__"` calls a class method (`CalendarAPI.main()`, `TrayAPI.serve()`). Shared declaration sets get their own class rather than leaking into a page's MRO (`LaunchFieldsAPI`).

## LOGGING CONVENTIONS
Logs must be short, objective, informative, visually distinctive.
1. **Message Format:** `<Category> Operation: <Outcome> (<primary detail>)`; join extra fields with ` · ` (`Phase Warmup: Completed · 1.20s · 205 Ticks · 41 Bars`).
2. **State Transitions:** `[StateA] → (Reason) → [StateB]`; `→` is reserved for transitions. True changes at `Info`, self-loops at `Debug`, hot-path self-loops silent (`reason=None`).
3. **No Commas or Periods:** ` · ` in place of `,`; one sentence per message; no end-of-sentence periods.
4. **Debug vs Info:** `Info` is strictly trading/execution and periodic trader-useful information; `Debug` is everything else.
5. **Errors:** `<Category> Operation: Failed · <Reason>`, reason capitalized.
6. **Tags:** positional only — no `Class`/`Subclass` arguments. The owning object resolves from the calling frame and always leads (`type(self).__name__`, falling back to the module). With no tags the subsystem is appended (`Library/System/Realtime.py` → `System`); with tags they replace that default and render in order. `LoggingAPI()` in `BufferAPI` gives `BufferAPI - Database`; `LoggingAPI("Buffer Management")` gives `BufferAPI - Buffer Management`. `identify=False` drops identity entirely. Process-wide run identity (provider · ticker · timeframe) belongs in `LoggingAPI.set_shared_tags(...)`, rendered *before* the level.
7. **Capitalization:** Title Case for fixed labels and nouns; capitalize the leading word of free-text reasons.
8. **Verbose Levels:** entry points set both primary sinks explicitly through a logger instance — `log.console.set_level(...)` / `log.file.set_level(...)` — never through the class. Sinks are process-wide, so the outermost `with log:` locks them. Use `with log.console.temporary(...)` for a scoped change.
9. **Lazy Messages:** pass a `lambda`, never a built string — `log.debug(lambda: f"...")`. A rejected record costs ~128 ns instead of rendering a thrown-away f-string or dataframe. Capture loop/`except` variables with default arguments (`lambda error=error: ...`). Bare constants are fine.

A rebuild **counts rows before dropping** and refuses on disagreement. Only the Postgres path is proven against a live server; Oracle and SQL Server carry statement-shape tests only. **`scope()`** binds one connection to a unit of work; nested `attach()` reuses it (`ContextVar`, lazy, released at block exit, never reused across scopes). - **Two thresholds decide who may use and who may change — on a credential, a workflow and a task.** `ViewRole`/`EditRole` on `Credential`, `RunRole`/`EditRole` on `Workflow` and `Task`, each a `RoleAPI` level meaning "this role and above", each validated on save: **`Public` is refused**, **null means owner only** (plus `Administrator`, who reaches everything), **neither may exceed the setter's own role** — a higher threshold would lock the creator out of what they just created — and **`EditRole` is at least `ViewRole`**, since the edit form reveals the value. The owner always keeps access, and a user who owns rows cannot be deleted. **Enforced in both managers through `AccessAPI`, 2026-09-23:** every mutating call takes `by` — a user UID is checked, `MISSING`/`None` is a trusted framework caller (the installer, the daemon, a script), and an unknown UID is refused. Only a signed-in user may create; a non-`Administrator` may only own what they create; only the owner or an `Administrator` transfers; an unchanged threshold above the editor's role survives an edit (only a *changed* value is capped); a create over an existing UID needs `Edit` on it; joining or leaving a workflow needs `Edit` on the workflow; skip, cancel, approve, reject and retain need `Run` on the run's task, delete needs `Edit`. **Both thresholds default to null (owner only)** — the one default that never trips the cap. Consumers may `from Library.Statistic.Label import *` — the one sanctioned star import, because a label module is nothing but constants.
- **`Library/Strategy`**: `StrategyAPI`, `StrategyType` (`Download` 1, `NNFX` 2, `DDPG` 3, `Trend` 4 — mirrored to C#). Constructor takes all seven `Parameter` sections in canonical order. `Rule/` = `Download`, `NNFXStrategyAPI` (money/risk base), `TrendStrategyAPI` (adds signals); `Hybrid/DDPG.py` = `DDPGStrategyAPI`, **a sibling of NNFX not a subclass** — it owns its sizing via `Model/Action.py` and deliberately has none of the NNFX stop/scaling machinery. **`Catalog.py` is the single strategy registry** — `CatalogAPI` (`STRATEGIES`, `CATALOG` keyed by `StrategyAPI.key()`, `DEFAULT`, `resolve`); `Main` and the web pages read it, never a second list. **The parameter value syntax lives here too:** `Syntax.py` (`SyntaxAPI` — ` · ` between slots, `|` between alternatives, numbered stage bodies, value decoding) and `Range.py` (`RangeAPI` — `low..high:step` and its coarse-to-fine ladder); `Grid.js` mirrors both and `Tests/App/test_Assets.py` keeps them in step. **Parameters resolve through `Ladder.py`, not a folder tree:** `Defaults` in the class body, then overrides merged key by key global → provider → category → ticker → timeframe; most specific wins, a missing override is **not** an error. Overrides live in `inspect_persistent("Overrides")` as sparse deltas stamped with the run that produced them. This retired the 66-file `Library/Parameter` tree, which held only 11 distinct configurations.
- **`Auto` only resolves an indicator's declared ladder** — it reads `SlotAPI.ladder` off the technical indicator in the **leading** slot, so it is meaningful only from slot 2 onward. It has no meaning on a scalar such as `RiskPercentage`. `SpaceAPI.expand_parameter` **refuses** an `Auto` it cannot resolve, naming the parameter; it used to pass the *string* `"Auto"` through as a value. Switching `Baseline`'s window to `Auto` took Trend from 1 round to 3 (192 → 640 candidates).
- **`Library/System`**: The engine (`SystemAPI`, `SystemType`, `LifecycleAPI`, `RealtimeAPI`, `BacktestingAPI` + `DatasetAPI` tape, `LearningAPI`, `OptimizationAPI`). `Main.py` is the CLI entry point. `Space.py` holds the space algebra — `SpaceAPI` (`AUTOMATIC`, `SECTIONS` and every expansion, staging and inheritance step as class methods) plus `CandidateAPI` — split out of `Optimization.py`. `OptimizationAPI` is a **sibling of `LearningAPI`** — both orchestrate N backtests over `SplitAPI.walk_forward_folds` through the machinery on `BacktestingAPI` (`_walk_forward_` · `_folds_` · `_replay_` · `_dispatch_` · `_resolve_` · `_worker_` · `_fitness_`); `FitnessType`, `SelectionMode` and `ElectionMode` live in `Selection.py`. `SystemAPI` names the run folder (`RUNS` · `INPUT` · `OUTPUT` · `RESULT` · `MANIFEST` · `PARAMETERS` · `CONTRACT`). **Three decisions, three scopes:** `--fitness` measures one run · `--selection` picks the winner *inside* a fold · `--election` picks one *across* folds (`First` · `Worst` · `Frequency` · `Mean` · `Median` · `Best` · `Last`). A fold's model is scored on its **validation** window, never its training window, and the held-out `--testing` pass is **the only unbiased number**. The elected model then runs **twice** — on the held-out window for that number, and over the full range to supply the curve that overlays the walk-forward stitch. **Artifact policy is uniform:** candidates and seeds write nothing; only the elected/full-range run emits, and only for the flags passed. `deliverables(report, export, plot)` scopes them to that run and `quieted(level)` drops both sinks to `Warning` for non-delivering passes. **`--risk-free` and `--benchmark` reach every offline system** — until 2026-09-17 `output_parser` accepted both everywhere while `LearningAPI` took neither the rate nor a worker payload carrying it (every fold's ratios were computed at 0) and `OptimizationAPI` ignored the benchmark. `_dispatch_` now carries `risk_free` for both workers, and `_report_` builds bars and benchmark series **only for a delivering run**, so a candidate or seed pass never pulls a benchmark.
- **`--continuous` interacts with election and must be reported as such.** Continuity makes folds path-dependent — every fold starts near the previous winner — so `Frequency` election becomes near-tautological because the folds agree by construction. With `--continuous`, `Last` or `Mean` is the honest choice and the run should record which it used.
- **The overfitting budget compounds; it does not reset per stage.** Stages turn a product into a sum (6→2→2→1 is 24 combinations flat, 11 staged) and coarse-to-fine turns a sweep into a funnel, so both cut trials. But stage 3 is conditioned on winners already fitted to the same data, so the effective trial count is the **accumulated total across every stage, round and fold** — which is what a run records, so a deflated metric can be computed against the real number.
- **`Library/Universe`**: `UniverseAPI`, `ProviderAPI`, `CategoryAPI`, `TickerAPI`, `ContractAPI`, `SecurityAPI`, `TimeframeAPI`.
- **`Library/Utility`**: Helper library. **Three persistence tiers, one derived root, no OS-temp dependency:** `inspect_root()` is `<platform data dir>/<App>` where `<App>` is the project root folder name (`inspect_application()`) and is never hardcoded. `inspect_temporary(*folders)` → `<root>/Temp` (pruned by age) · `inspect_persistent(*folders)` → `<root>/Data` (saved runs, weights, overrides — retention never sweeps it) · `inspect_cached(*folders)` → `<root>/Cache` (preload tapes, pruned by **last use** — `_read_cache_` touches `meta.json` on every hit because `PruneAPI.newest` reads the newest *file*, so touching the folder would silently do nothing). `inspect_destination(value, *folders)` turns a flag into a destination. **Reach for the helper before writing the idiom** (audited 2026-09-15 across the whole framework, 211 duplications removed): files through `IO` (`read_/write_` `text`/`json`/`yaml`, `mkdir`, `remove`, `copy`, `copy_tree`) · ageing through `File.PruneAPI` (`DAYS`, `horizon`, `sweep`, `prune`) · processes through `Runtime` (`windowless`, `terminate`, `find_host`, `split_arguments`/`join_arguments`) · `EnumerationAPI.names()` for enum choice lists · `Typing.normalize` for fuzzy names · `Memory.memory_to_string` (1024-scaled, one decimal) · `Datetime.STAMP` for folder stamps and `Datetime.INSTANT` for a displayed or typed instant · `Parameter.first` · `Tray.TrayAPI` for the Scheduler and Web tray apps. Outside Utility: `LoggingAPI.failure` for an Error+Exception pair, `DatapointAPI.reference`/`_relate_`, `DatabaseAPI.primary`/`where`/`first`/`records`/`update(parameters=)` instead of hand-written SQL. Frame helpers own logging identity: `find_caller_frame`/`find_frame_class`/`find_frame_module`/`find_frame_package`.
- **The web app never ships a secret to a browser.** The credential grid is built from masked rows (`CredentialManagerAPI.credentials`), and only an explicit **Reveal** — an `EditRole` holder, one row at a time — fetches plaintext, which lands in its own panel above the grid as one closed toggle per key and is cleared by **Hide** or by any new selection. The edit form never carries the stored secret. **Buttons gate on the reader's `Access` column** — `App/V2/Assets/Callbacks/Gate.js` (Scheduler Edit/Run/Delete), `GateAccess.js` (credential Edit/Reveal/Delete), `GateSkip.js` and the enable segment — and the server refuses regardless, so a gate is a courtesy, never the control. A refusal must `return dash.no_update`, never `raise PreventUpdate`: notifications travel by `dash.set_props`, and Dash discards them when a callback raises.
- **`Library/Web`**: The Quant Cognition application — the composition root wiring `Library/App/V2` into the deployed Dash app plus the domain pages. **Organized by father route**, one folder per section: `Trading/` · `Research/` (Launch · Result · Backtesting · Optimization · Learning · Research) · `Strategy/` · `Scheduler/` (Base · Entity · Task · Workflow · Run) · `Framework/` (Database · Hierarchy) · `Core/` (Artifact · Status · Managed, the shared plumbing — `ManagedPageAPI` is the one base for the Result and Scheduler page families) · `Service/` (Serve · Tray · Tunnel), with `App.py` and `Launchpad.py` at the root. `Service/` is deliberately **not** re-exported by the package `__init__`, so importing `Library.Web` does not drag in waitress and pystray. `Assets/Callbacks/` holds the four callbacks that speak Scheduler vocabulary (`Cron` · `GateLive` · `GateRuns` · `GateSkip`); everything generic stays in `App/V2`. `Research/Launch.py` declares the CLI surface as `FieldAPI` tuples on `LaunchFieldsAPI` (`MARKET` · `BACKTESTING` · `OPTIMIZATION` · `LEARNING` · `OUTPUT` · `SYSTEMS` · `TASKS` · `EVERY`) so one declaration drives the modal, its defaults **and** the command string; `LaunchAPI.launch_callbacks` wires it. A result detail page renders an immutable artifact and therefore **does not poll** — polling re-mounted the grid and discarded sheet tabs and chart zoom. Strictly separated from `Library/Scheduler`; the only sanctioned coupling is the Scheduler page consuming `ManagerAPI`. Footer mottos load from the root `MOTTOS.md` (one quote per `- ` line). **The Scheduler runs the web app through `Script/Environment/Server.py` and the tunnel through `Script/Environment/Tunnel.py`** — `Library/Web/Service/` keeps only the tray class, and the app's identity (name · host · port) is `WebAppAPI.build()`. **Desktop and iPad 12.9" are both first-class** — a page is not done until it works on touch as well as mouse. An embedded figure that does not *need* zoom must not capture touch gestures (a Plotly DAG that swallowed one-finger drags made the page unscrollable): set `xaxis.fixedrange`/`yaxis.fixedrange` true, `dragmode` false, `config={"scrollZoom": False, "doubleClick": False, "displayModeBar": False}` — but never `staticPlot: True` when clicks are still wanted, as it kills click events too. Prefer "fits without interaction"; verify at 1024×1366 CSS px, not just desktop.

- **`Tests/Golden/`** holds the golden artifacts themselves, not tests. **Two halves, because there are two engines:** `Online/Golden 1-5` are `Simulation` runs of `RealtimeAPI` driven by the Connector cBot in cTrader — their P&L arrives over the wire, so agreement with cTrader there is largely tautological; `Offline/Golden 1-5` are CLI `Backtesting` runs of `BacktestingAPI`, which computes its own fills and fees and is the engine Phase 3 targets. **Compare `Offline/` against cTrader for accuracy; compare either against itself across a change for regression.** Each folder holds `Run.json` · `Parameters.yml` · `Contract.yml` · the five exports — `Contract.yml` is what lets a golden replay at all, because `Universe.Contract` is overwritten by every online run. ### Script (`Script/`)
- **All script code lives here, none in `Library/`.** Argument parsing, `main()` and `if __name__ == "__main__"` belong to `Script/`; `Library/` holds library code only. Four standing exceptions, for now: the three CLIs `Library/System/Main.py`, `Library/Scheduler/Main.py` and `Library/Credential/Main.py` — each module's CLI lives beside the module it drives, and how the growing set is organised is an open question — and `Library/Scheduler/Runner.py`, the daemon's own child process (moving it would make `Library` depend on a `Script` path). A script bootstraps `sys.path` from its own depth (`parents[2]` inside a subfolder) — the one sanctioned path arithmetic.
- **Layout — one folder per Scheduler workflow, named after it, and a task's path mirrors its UID** (`Setup.Auth` → `Script/Setup/Auth.py`): `Scheduler.py` (the boot launcher) · `Install.py` (registrar) · `Task.py` (shared plumbing) · `Web.py` (debug run of the web app) · `Python/` (`Conda` · `UV` · `System` environment updaters) · `Setup/` (the provisioning DAG, the `Enum` generator and its seven block providers, and the one-off `Timezone` and `Reload` migrations) · `Environment/` (`Cache` · `Retention` · `Version` · `Update` · `Credential` · `Tunnel` · `Server`) · `Market/` (`Calendar` and `Horizon` — **`HORIZON` = 2014-01-01, the earliest date the market-data services download**; a download passes it into `Library` as `start`).
- **Every stored task path points into `Script/`,** so moving `Library` code never breaks a Scheduler row. A script that only wraps a library class stays three lines (`Environment/Server.py` builds `WebAppAPI.build()` into the web tray; `Market/Calendar.py` calls `CalendarAPI.download`). Moving a script means updating `Scheduler.Task.Path` — `python -m Script.Install --register` re-registers without provisioning, but it rewrites every field of every task (including `Enabled`), so for a pure move update `Path` alone through `ManagerAPI.update_task` and confirm every stored path exists.
- **One boot entry.** Windows Task Scheduler runs only the master orchestrator (`Quant Scheduler` logon task → `pythonw Script/Scheduler.py` → silent tray daemon). The daemon boot-launches service-bearing workflows, supervises services, cron-launches scheduled workflows and advances manual ones. `Scheduler.py` must stay importable when `Library` is broken — it catches `ImportError` to relaunch under conda, so it may not import `Library` at module level.
- **Three standard workflows** (registered by `Script/Install.py`, owned by `Script.Setup.Auth.ADMIN`): **`Setup`** (manual) = the FK-ordered provisioning DAG (`Enums` · `Auth`→`Credential`→`Logging`→`Scheduler` · `Universe`→`Market`/`Portfolio` · `Indicator`, all `Tolerates=false`; `Credential` follows `Auth` because its `Owner` references `Auth.User`, and `Logging` precedes `Scheduler` because `Run.LID` references `Logging.Log`); **`Environment`** (daily `0 4 * * *`) = `Cache` → `Retention` → `Version` → `Update` → `Credential` → `Tunnel` → `Server`; **`Market`** (daily `0 6 * * *`) = `Market.Calendar`.
- **Provisioning tasks** (the `Setup` workflow) are idempotent modules with a uniform `main(database="Quant") -> int` — re-run any task or the whole DAG safely; each also runs standalone (`python -m Script.Setup.Auth`). Of the `Environment` tasks, `Cache` · `Version` · `Update` touch no database and take no `database` argument; `Retention` takes one because it also prunes `Logging.Log`.
- **Shared plumbing is `Script/Task.py`** — `migrate(db, *datapoints)`, `attempt(log, name, work, *, detail)` (runs a callable, logs Completed/Failed, returns the exit code) and `provision(log, name, work, *, database, detail)` (`attempt` inside a Postgres connection). **Both take the logger and never build one** (see the logger-identity trap). `Logging`, `Universe`, `Market`, `Portfolio`, `Scheduler` and `Indicator` use `provision`; `Auth`, `Enum` and `Update` use `attempt`.
- **The enum block providers declare, they do not run.** `Action` · `Position` · `Strategy` · `Stream` · `System` · `Update` are five-line modules exporting one `*_block()`, and `Logging` exports `logging_block()` beside its provisioning task; `enum_block(name, enumeration)` takes the enumeration itself. `python -m Script.Setup.Enum` is the single entry point. Guard any generator change with the output hash — the committed `Enum.cs` is `82087810f5c09c37` (sha256, first 16; its header names `Script/Setup/Enum.py` since 2026-09-17).
- **One-off migrations live in `Script/Setup/`** — `Timezone.py` (local → UTC stamp conversion) is dry-run by default, applies once, and records a marker; it is not part of any workflow. `--apply` runs every column in one transaction and writes the marker only after the commit. `Reload.py` rebuilds `Market.Tick` as a compressed `timestamptz` hypertable (`Market.TickReload`) beside the original, one 31-day chunk per security at a time, each verified by row count and an XOR row hash before it is compressed; dry-run by default, resumable from its marker, and it never touches the source table.
- **Entry point:** `python -m Script.Install [--database] [--boot] [--register]` provisions in-process, registers the workflows, with `--boot` creates the Windows logon task, and with `--register` only re-registers.
