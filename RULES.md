# Quant Trading Framework Project Guidelines

## PROJECT OVERVIEW
A **multi-purpose Quant Trading Framework** built around **cTrader**.
- **Root Folder:** `cAlgo` (in Documents for cTrader compatibility).
- **`Library/` (Python):** Core logic, AI models, trading systems, persistence, Dash frontend.
- **`Sources/` (C#):** cTrader Robots, Indicators, Plugins — bridged to Python via shared memory (named `mmap` + auto-reset Event, single-slot request/response lockstep).
- **`Tests/` (Python):** Pytest suite mirroring `Library/`.
- **`Setup/` (Python):** Zero-to-hero provisioning (`Setup/Install.py`) + registrar for the three Scheduler workflows.
- **`Script/` (Python):** Boot launcher + environment helpers.
- **`Research/` (Python):** Frozen research method per campaign.

The short-side gap in runs 1-4 (24.11 · -1.30 · 25.65 · 29.54) **equals that position's mark-to-market gap exactly** — cTrader closes it at the final tick of the window and charges its closing commission and full swap, we mark it earlier. Our `truncate(x, 2)` reproduces cTrader's cent quantisation by hand-check (1000 units → 0.045 → 0.04, an 11% effect on run 2) but has **not** been proven in a run.
- **`net.csv` had four defects, all fixed 2026-09-11, all from one place.** `generate_net_report` concatenated the trades and positions frames on `list(set(...).intersection(...))`, which (a) dropped `Position` — absent on `PositionAPI` — so `aggregate_items` returned its input unchanged and **the entire Aggregated half silently became a copy of Individual whenever a position was open** (85 of 85 rows on golden 1); (b) dropped `ExitTimestamp`, so holding time collapsed to `stop - entry` (avg 181.64 days for an H1 year); (c) ordered columns non-deterministically. And `initial_balance` was `account.Balance`, the **closing** balance, so every balance-relative percentage divided by the wrong number — `Max Balance Drawdown (%)` read 44.24 where `absolute / peak balance` gives cTrader's 31.64. The fix is `_aligned_positions_` (open position takes its own `UID` as `Position`, a null `ExitTimestamp`) plus the trades' column order, and `initial_balance` from `equity_curve[0]`. **`calculate_excursion` and `calculate_holding_times` were always correct** — the report path fed them the wrong frame and the wrong balance.
- **Epoch conversion: two pairs, and they must agree.** `datetime_to_epoch`/`epoch_to_datetime` are pure arithmetic against a naive `EPOCH` and were always timezone-neutral — `BacktestingAPI` uses them, which is why the offline goldens never moved. `datetime_to_timestamp`/`timestamp_to_datetime` used `.timestamp()`/`.fromtimestamp()` and were therefore **local-dependent**, so `RealtimeAPI` stored cTrader's UTC wire stamps as naive **local** time, off by the UTC offset and shifting across DST. Fixed 2026-09-11: the epoch is always read as UTC and a new `zone` argument only decides the label — `None` gives **naive UTC**, a zone gives an aware datetime. `utc_now(zone=None)` is now the single source of "now". **Everything in the framework is naive UTC unless a boundary explicitly asks for a zone.** Do not reintroduce a second convention.
- **`truncate`'s tolerance is load-bearing.** `Utility/Math.TOLERANCE` is `1e-6` and reproduces cTrader's cent quantisation of commission (`Backtesting.py:581`, proven on golden 2 where 1000-unit trades make 0.045 → 0.04 an 11% effect). It is named rather than inline so nobody "tidies" it — changing the value changes every commission figure in the goldens.

Long/short and absolute/percentage splits both collapsed a hypothesis that a total alone supported.

EURJPY and US500 have `Security` rows but no data (1000 defined, 7 populated). **Bars are session-stamped at 22:00 (21:00 DST)** — a Thursday-stamped D1 bar *is* Friday's session, D1 carries 5 bars/week stamped Sun-Thu; an audit against a calendar-day calendar reports every Friday missing, which is convention not loss. **2016-01-11 → 2016-01-25 is absent in all seven pairs, ticks and bars, and is not repairable** — proven 2026-08-25 by a re-download that visited the month and wrote zero rows for those days. Do not spend another download on it; it predates the thesis and is uniform across pairs, so it does not bias comparison.

A table whose physical order drifted is out of date even with every column present and correctly typed, so `migrate` rebuilds it. `Market.Tick` was last: 926,936,168 rows · 148 GB · 247 min, row count preserved, five `Bar`→`Tick` foreign keys realigned. `Ask - Mid - Bid` on `Tick` is deliberate, not alphabetical drift.
- **Every run owns a folder, and the CLI mints it.** `Main` takes `--run FOLDER` or mints `<Temp>/Runs/<uid>`: `Run.json` (manifest · command · scope · parameter provenance) · `Run.log` · `Input/Parameters.yml` (what actually resolved, so a later override cannot rewrite history) · `Output/` with `Result.json` · `Export/*.csv` · `Plot.html` · `Weights/`. Bare `--export`/`--plot`/`--profile` resolve into `Output/` via `SystemAPI._destination_`, so the executor passes `--run` and nothing else. **`Result.json` is the data; `Plot.html` is only a viewer** — the web app reads the payload directly, which is what made `--plot` optional again (95% of a 4.9 MB H1 plot was payload).
- **`Run.Retention` decides location, not just pruning.** `Temporary` → `<Temp>/Runs`, `Persistent`/`Favorite` → `<Data>/Runs`; Save and Release move the folder (a rename — same volume) and `ArtifactAPI` resolves either tier. Retention prunes the temporary root by age and **cannot reach** the persisted one — a structural guarantee, which deleted the whole `protected()`/`spared()` mtime-window matcher. Level is changeable only once the run has finished, so nothing relocates a folder a live process is writing.
- **Three log sinks, one owner each.** Console ephemeral (`--console`, Debug) · File is the complete record (`--file`, Debug) writing `Run.log` **inside the run folder**, so run processes never touch the shared rotating entry-point log · Database temporary (`--storage`, Warning default, Debug allowed). The executor captures the child's stdout only to parse progress and catch what bypasses the logger: `_sift_` filters to the storage level but **always keeps lines with no log prefix**, and `_rescue_` appends them to `Run.log`. That is what makes `Run.log` the source of truth — a native crash or a pre-logging argparse failure writes where no Python hook can see it.
- **The warmup window belongs in the cache key — the tick tape does not.** `BacktestingAPI._preload_` keys on `(security, start, stop, timeframe, auto, resolution, window)`. Omitting `window` let the first candidate's warmup define every later one's (a 30-period baseline ran on a 21-bar warmup; serial disagreed with parallel). Nothing was mutated — `DatasetAPI` is read-only. But keying the *whole* dataset per window was wrong granularity: measured, **0.7%** of a rebuild (bar frames) depends on the window, **99.3%** (the tick tape) does not. `_tape_` caches `_acquire_frames_` on a **window-free** key, so six windows load the tape once. `OptimizationAPI._ordered_` groups candidates by technical parameters to keep the cheap per-window rebuild consecutive (192 EURUSD D1 candidates: 26.96s → 19.09s, scores identical).
- **Do not warm every candidate to the grid's worst-case window.** Self-consistent but breaks standalone reproducibility: on 192 candidates **160 scores changed** (SMA/20 0.4179 → 0.4271) and the top-10 shifted. It also makes a score depend on grid membership.

- **Torch:** 2.13.0+cpu, 24 threads. `Library/__init__.py` preloads `libiomp5md.dll` before MKL and sets `KMP_DUPLICATE_LIB_OK` — **do not delete**. Pin torch in the pip section of `Quant.yml` so `--prune` cannot clobber it.

## OPERATIONAL TRAPS (each of these has cost hours)

- **Learning CLI:** `--timeframe Hour` / `Daily` — the *friendly* parameter-tree key, never `H1`/`D1`. A missing key **auto-vivifies an empty node** and fails silently.
- **Learning verbosity:** never run H1/large-bar Learning at `Info`/`Debug` — per-bar log flood costs ~0.6s/bar (a 9h hang for one episode). Use `Warning`; spawn workers too.
- **`LearningAPI._export_`** has a signature collision — run with `export=False`.
- **Logging:** silence via sink levels (`log.console.set_level(...)`), never stdlib `logging.disable()` — the fast path bypasses stdlib. `VerboseLevel` is ordered by **verbosity**, so `Debug` is the largest value and a sink accepts `record <= sink` — the inverse of stdlib.
- **Logger identity comes from the calling frame.** A logger built in `Setup/Market.py` renders `Market - Setup`; the same call moved into a shared helper renders `Task - Setup`. Never construct `LoggingAPI()` inside a helper on behalf of a caller — pass the logger in.
- **Console encoding:** `·`/`→` crash cp1252 stdout — use `conda run --no-capture-output` and/or `PYTHONIOENCODING=utf-8`, plus `sys.stdout.reconfigure(encoding="utf-8")` in standalone scripts.
- **`QueryAPI` placeholders:** raw SQL cannot use `::type` casts — `::name::` is the interpolation token. Use `CAST(x AS text)` / `to_char(...)`.
- **A table rebuild is not reversible by hand.** `migrate` renames to a temp, recreates, copies, drops — and a rename **carries inbound foreign keys onto the temp**, so without `realign` the drop either fails or silently strips integrity. A `GENERATED ALWAYS` identity rejects a plain insert, aborting the copy *after* the rename and leaving data in `<Table>_<hex>` — recoverable only if the temp survives. Never let a rebuild drop the temp on an unverified row count.
- **Connection count is a correctness budget, not a tuning knob.** Postgres here is `max_connections` 400. Anything holding connections needs a hard ceiling and a return path — verify with a soak (`pg_stat_activity` must plateau), never by watching a page feel faster. A thread-local cache is not a pool: one grew to 409 clients and was reverted.
- **BLAS in standalone scripts:** calling `np.corrcoef`/LAPACK without importing `Library` first can abort the process (exit 127) — set `KMP_DUPLICATE_LIB_OK=TRUE` or import `Library`.
- **ProcessPool cleanup:** kill worker **children before parents**; orphaned `spawn_main` workers hold ~2 GB each at 0% CPU forever.
- **`psutil` cmdline filters** match your own `python -c "...script.py..."` probe — exclude `os.getpid()`.
- **This repo lives under OneDrive** — `shutil.rmtree(..., ignore_errors=True)` fails silently on sync-locked paths; pass an `onerror` handler and verify with `path.exists()`.
- **Never conclude "no callers" from a truncated search.** A `grep | head` that fills with unrelated matches reads as a clean result and is not one.

## CODING PHILOSOPHY
1. **Precision & Accuracy:** correct, working code over speed.
2. **Simplicity:** do not over-engineer. As simple, concise, readable and performant as possible.
3. **Measure, Don't Guess:** profile before optimizing (`cProfile` by cumulative + tottime, targeted micro-benchmarks). Validate hypotheses with data.
4. **No Environment Configuration:** no `QUANT_*` (or other) environment variables — behavior comes from constructor arguments and CLI flags only.
5. **Generic, never special-cased.** Do not branch on the current context (`if strategy == Download`); keep parallel components symmetric. A special case that solves today's problem is a rule the next component has to know about.
6. **The online backtest is the hot path** — a real strategy, `Transform.Market=True`, the full engine. Optimize against that, not against a synthetic loop; construction machinery is usually the real target.
7. **Never run a destructive operation against real data while validating.** Create throwaway rows, on a fresh page with no leftover selection, verify the exact target, then clean up and confirm by query that only your rows changed. A live-DB Scheduler UI validation once deleted a real task because an earlier step had left it selected and multi-select made Delete act on it; its run history was unrecoverable.

## RESPONSE STYLE
Lead with the conclusion, prefer **bullet points and tables** over prose, omit filler. Long-form paragraphs only when explicitly requested.
**No standalone HTML dashboards as deliverables** — the web app and cTrader's own equity/trade view are the user-facing visualization surfaces; analysis tools in the scratchpad are fine. After a Learning run, name the exported weights folder so it can be referenced: `{strategy name minus the StrategyAPI suffix} {date} {time to seconds}` (e.g. `HybridRDDPG 2026-07-07 13-33-21`) — seconds are in the stamp so no two runs collide and no learned model is ever lost.

## CODING STYLE & ORGANIZATION
1. **Language:** **English (US)** spelling (`Optimization`, `behavior`). Exception: identifiers mirroring an external API verbatim (cTrader's `Cancelled`).
2. **General:** No docstrings or comments. Tidy files (no trailing spaces), **one blank line before a `class` definition**, one blank line after `class` and between methods, and **no trailing newline at EOF**. (Exceptions by explicit request: paper-mapping docstrings in `Library/Model/Method/DDPG|SAC|TD3`, `Library/Model/Core/Noise`, `Library/Strategy/Model` and `Library/Strategy/Hybrid/DDPG.py` — kept for the thesis, including the reward-clipping comment in `Strategy/Model/Reward.py`; API-surface docstrings in `Library/Bloomberg`, `Library/Database`, `Library/Logging`. Do not strip these.) **In the docstring-keeping modules only public API methods get one** — private `_methods_` never do; one documented private among undocumented peers reads as noise.
3. **Naming:** `CamelCase` public members; `_naming_` private; `UPPER_SNAKE` public constants; `_UPPER_` private class constants. Lowercase `__post_init__` arguments. Paired verbs are `start`/`stop` (never begin/end or open/close); the domain noun is `security`, never `symbol`/`instrument`; private data access is `_fetch_` (read) and `_execute_` (write); every API class carries the `API` suffix.
4. **Typing:** simpler types first in a union — `str | MyClass`, never `MyClass | str`. `Self` from `typing_extensions` for instance returns (3.10 compatibility). `from __future__ import annotations` only when forward references require it — a self-reference, a later class, a `TYPE_CHECKING`-only name, a name the module never imports at all, or a class attribute shadowing a type (`Logging/File.py` has a `Path` property, so `Path | str` inside that class body needs the future import). Prefer built-in types over `typing` classes (`type[X]`, never `Type[X]`).
5. **Imports:** sorted ladder-style block; one blank line between external and project (`Library.*`) imports; explicit imports for internal modules. A call or an import is either **entirely on one line or exactly one name per line** — never fill-style wrapping. Package `__init__.py` re-exports run least to most important (flagship API last) — and anything imported there must also appear in `__all__`. Always import `np`/`pd`/`pl` from `Library.Database.Dataframe`, never directly, so the shared display configuration applies — the only exceptions are `Dataframe.py` and its import closure (`Database.Dataclass`, `Utility.Typing`).
6. **Callbacks:** never reference a component by raw string — pass the `ComponentID`, qualified by the declaring class when the reference crosses a class body (`State(SchedulerBaseAPI.TARGET_STORE_ID, ...)`). Declare each shared identifier **once**, on the lowest common base, and let subclasses bind it in `ids()`. Resolution is by name, so a string works — it just hides typos until runtime.
7. **Density:** dense method bodies without internal blank lines (except complex `__init__`); standard spacing in signatures and assignments.
8. **Architecture:** order methods by category (Connection → Disconnection → Business) then by complexity (simplest first); private before public; fields, properties and methods run least to most important. `@staticmethod` for stateless logic, `InitVar` for temporary inputs. Shared helpers live in `Library/Utility` — promote repeated logic there instead of duplicating it.
9. **No path arithmetic.** Never `Path(__file__).parent...` — use `Library/Utility/Path.py` (`traceback_root()` for the repo root, `inspect_module(__file__)` for a module's own folder). The single exception is the `sys.path` bootstrap in a standalone entry point, which by definition runs before `Library` is importable.
10. **Dataframes:** capitalize framework-level columns (`Date`, `Security`). Prefer Polars (`pl`); Pandas (`pd`) for compatibility.
11. **Dataclass class constants carry no annotation.** `_DEPTH_ = 3` is a class attribute; `_DEPTH_: int = 3` is a fourth constructor field. Verify with `fields(Cls)`.
12. **`Structure` merges the parent with `**super().Structure` as the last entry** — one idiom, parent columns after the child's, so the physical order is the declaration order. The exception is a child that redeclares parent columns (`TradeAPI` over `PositionAPI`): there the explicit merge loop keeps the child's declaration and lets the parent only fill the gaps, so it is load-bearing, not drift — replacing it reorders or retypes columns and `migrate` would rebuild the table.
13. **Shared status sets live on the datapoint** (`RunAPI.Busy` · `Live` · `Active` · `Open`), never as private tuples on the consumers that read them.
14. **Explicit over loops for small fixed sets.** One line per named attribute, not a tuple-loop — a reader should see the names, and a typo should be a failure at the line that owns it.
15. **Boolean CLI flags are `store_true`** (present = True, absent = False), never `BooleanOptionalAction`.
16. **The `MISSING` sentinel** (`from Library.Utility.Typing import MISSING, Missing`; `Missing.__bool__` is False) marks "not supplied" where None is a legitimate value — `DatabaseAPI` routing params (`database`/`schema`/`table`/`legacy`) and `InitVar` resolution inputs on datapoint models. **Plain persisted datapoint fields default to `= None`** and are not a `MISSING` case.

## LOGGING CONVENTIONS
Logs must be short, objective, informative, visually distinctive.
1. **Message Format:** `<Category> Operation: <Outcome> (<primary detail>)`; join extra fields with ` · ` (`Phase Warmup: Completed · 1.20s · 205 Ticks · 41 Bars`).
2. **State Transitions:** `[StateA] → (Reason) → [StateB]`; `→` is reserved for transitions. True changes at `Info`, self-loops at `Debug`, hot-path self-loops silent (`reason=None`).
3. **No Commas or Periods:** ` · ` in place of `,`; one sentence per message; no end-of-sentence periods.
4. **Debug vs Info:** `Info` is strictly trading/execution and periodic trader-useful information; `Debug` is everything else.
5. **Errors:** `<Category> Operation: Failed · <Reason>`, reason capitalized.
6. **Tags:** positional only — no `Class`/`Subclass` arguments. The owning object resolves from the calling frame and always leads (`type(self).__name__`, falling back to the module). With no tags the subsystem is appended (`Library/System/Realtime.py` → `System`); with tags they replace that default and render in order. `LoggingAPI()` in `BufferAPI` gives `BufferAPI - Database`; `LoggingAPI("Buffer Management")` gives `BufferAPI - Buffer Management`. `identify=False` drops identity entirely. Process-wide run identity (provider · ticker · timeframe) belongs in `LoggingAPI.set_shared_tags(...)`, rendered *before* the level.
7. **Capitalization:** Title Case for fixed labels and nouns; capitalize the leading word of free-text reasons.
8. **Verbose Levels:** entry points set both primary sinks explicitly through a logger instance — `log.console.set_level(...)` / `log.file.set_level(...)` — never through the class. Sinks are process-wide, so the outermost `with log:` locks them. Use `with log.console.temporary(...)` for a scoped change.
9. **Lazy Messages:** pass a `lambda`, never a built string — `log.debug(lambda: f"...")`. A rejected record costs ~128 ns instead of rendering a thrown-away f-string or dataframe. Capture loop/`except` variables with default arguments (`lambda error=error: ...`). Bare constants are fine.

Architecture detail lives in `ARCHITECTURE.md`. This map is the index plus the invariants that bite.

### Python (`Library/`)
- **`Library/App`**: Versioned Dash framework — `V1/` frozen legacy (critical bugfixes only), `V2/` active; consumers pin a version (`from Library.App.V2 import AppAPI`) and the versions share zero code. `AppAPI(ShellAPI, RouterAPI)` — Shell owns layout + navigation tree, Router owns path resolution and the single-paint route callback. **`V2/` is split into subpackages** — `Core/` (Callback · Injection · Identity · Layout · Router · Shell) · `Component/` · `Page/` · `Lightweight/` · `Session/`, with `App.py` at the root; the parent `__init__` imports **through** those packages, never past them into leaves. `AppAPI.Launchpad` names the root page class and `LaunchpadAPI._MATRIX_` pins its grid as `(columns, rows)` — empty keeps the CSS auto-fit. **An application may overlay the framework assets:** Dash keeps serving `App/V2/Assets`, while a folder named `Assets` beside the `AppAPI` subclass is consulted first by `asset()` and served at `/_application`. Repointing Dash's own `assets_folder` instead silently drops the auto-injected `Scripts/*.js` and the favicon. `Lightweight/` is the **only** charting/tabling system (Dash `DataTable` retired 2026-08-03). **The spec layer is `Library/Statistic/Workspace.py` and imports no Dash.** `Workspace.backtest(...)` is the single composition of a result view, rendered by both `--plot` and the web pages. **Artifacts are immutable** — a run's page renders the HTML written when it ran, so new panes do not appear on old runs.
- **`Library/Auth`**: Server-side authentication + RBAC on the Postgres `Auth` schema. `RoleAPI` (`Public` < `Viewer` < `Editor` < `Moderator` < `Administrator`), Argon2id `PasswordAPI`, `UserAPI`/`TeamAPI`/`OfficeAPI`, provider seam (Local · Cloudflare · OIDC), `AuthAPI`. Zero environment coupling: constructor params only (no secret ⇒ fresh random per process ⇒ restart forces re-login). Seeded by `Setup/Auth.py`.
- **`Library/Bloomberg`**: Bloomberg integration (`HistoricalAPI`, `IntradayAPI`, `ReferenceAPI`, `StreamingAPI`, `QueryAPI`).
- **`Library/Database`**: Abstraction layer (`DatabaseAPI`, `DataclassAPI`, `DatapointAPI`, `QueryAPI`, `EnumerationAPI`, dataframe utilities) over Oracle, Postgres, SQL Server. **Migration seam — four driver-specific hooks:** `disordered()` compares physical against declared column order; `_carry_()` returns the whole copy statement (a generated identity is lifted differently on every engine); `realign()` re-points inbound foreign keys a rename dragged onto the temp. A rebuild **counts rows before dropping** and refuses on disagreement. Only the Postgres path is proven against a live server; Oracle and SQL Server carry statement-shape tests only. **`scope()`** binds one connection to a unit of work; nested `attach()` reuses it (`ContextVar`, lazy, released at block exit, never reused across scopes). A clone differing only in schema/table **borrows** its origin's connection — refused for admin, a different database, a disconnected origin, or any non-autocommit connection. Measured: Scheduler render 154 → 38 ms, 4 connections → 1.
- **`Library/Engine`**: Generic multi-state-machine engine. Zero trading domain knowledge.
- **`Library/Formulas`**: Financial and utility formulas (`DateTime`, `Spot`, `Historical`).
- **`Library/Indicator`**: `Technical`, `Fundamental` (incl. the Forex Factory `Calendar` scraper), `Sentimental`, plus the umbrella `IndicatorAPI` — which owns the catalog and every `parse_*`/`resolve_*` as class methods.
- **`Library/Logging`**: The framework logger — 7 modules, API-surface docstrings. `Level.py` (`VerboseLevel`, ordered by verbosity, mirrored to C# — **never renumber**) · `Logger.py` (abstract sink, cached-second `stamp()`, class-level `Gate` so a suppressed record returns after one integer compare; `write()` never raises) · `Console.py` · `File.py` · `Storage.py` (durable DB sink, **one row per log not per record**, bounded queue + background writer, re-entrancy guard against `Library/Database`'s own logging) · `Logging.py` (the façade, a real `logging.Logger` subclass bypassing `_log`/`makeRecord`/`handle`; `install()` chains `sys`/`threading` excepthooks). Durable rows land in the Postgres `Logging` schema via `Log.py`, which `Scheduler.Run.LID` references `ON DELETE SET NULL`.
- **`Library/Market`**: `MarketAPI`, `BarAPI`, `TickAPI`, `PriceAPI`, `SeriesAPI`, `TimestampAPI`.
- **`Library/Model`**: `Core/` (`AgentAPI`, `NetworkAPI`, `MemoryAPI`, `Noise`) and `Method/` (`DDPG`, `SAC`, `TD3`), plus `Split.py` (walk-forward splitter).
- **`Library/Portfolio`**: `PortfolioAPI`, `AccountAPI`, `OrderAPI`, `PositionAPI`, `TradeAPI`, `SessionAPI`, `PnLAPI`. `Sizing.py` and `Statistic.py` are function modules, not classes — Sizing holds `SizingMode` plus the `calculate_*_volume` family; Statistic keeps only the Polars views, the five schema dicts and the report generators that are genuinely Portfolio-coupled, everything context-free having moved to `Library/Statistic`.
- **`Library/Protocol`**: Wire protocol shared with the C# Connector — `Action/` and `Update/`, `ActionID`/`UpdateID`.
- **`Library/Scheduler`**: DB-backed job orchestration on the Postgres `Scheduler` schema, replacing Windows Task Scheduler with one boot daemon. `WorkflowAPI` → `CycleAPI` (one execution of a workflow) → `TaskAPI` → `RunAPI`; `DependencyAPI` holds DAG edges, evaluated by `CoordinatorAPI`. One shared `Kind` ∈ {`Manual`, `Scheduled`, `Service`} spans the module. **Only the workflow `Schedule` opens a Cycle**; a member task's `Schedule` is an earliest-start gate *inside* it, never a trigger. `ManagerAPI` is the single mutation authority behind console, CLI and web. **A suspension is not a failure** — `_service_` closes the run `Success` stamped `Suspend` when the daemon itself terminates a service for maintenance; leaving it to the reaper recorded 29 healthy tunnel runs as crashes. `ManagerAPI` opens a connection per call deliberately.
- **`Library/Spotware`**: cTrader Open API provider (`SpotwareAPI` with `UniverseAPI` · `MarketAPI` · `StreamingAPI` · `PortfolioAPI` · `ExecutionAPI`). **No shared provider base class** — each provider stands alone on `ServiceAPI` + `DataframeAPI` until many providers pull genuinely different kinds of data (`PLAN.md` §1.3). Output keys include `Symbol · Ticker · Timeframe · Timestamp · Ask · Bid · Open · High · Low · Close · Volume · Quote · Size · Action`; `Symbol` is cTrader's numeric id, **not** a framework `Security`. **Everything leaving the module is decoded, and everything entering is encoded, by the root's helpers — never inline:** prices from 1/100000, money by `moneyDigits`, volumes cents ↔ units, timestamps as exact integer milliseconds to naive UTC (`_epoch_`/`_stamp_` over `Utility/Datetime`), and wire enums through the vendor's protobuf descriptors (`_code_`/`_named_`), whose decoded names equal the framework's enum member names. Subscriptions go through one `_listen_`. Absolute stop loss and take profit are unsupported on `MARKET` orders, so market and range orders take relative distances.
- **`Library/Statistic`**: Context-free trading analysis, a foundation layer beside `Utility` — it imports nothing from Market, Portfolio, App or System. `Label.py` (118 metric-name constants) · `Metric.py` (30 pure calculations) · `Series.py` (6 equity series) · `Payload.py` (11 payload readers) · `Workspace.py` (the Dash-free chart/table spec classes) · `Composition.py` (13 view compositions). Consumers may `from Library.Statistic.Label import *` — the one sanctioned star import, because a label module is nothing but constants.
- **`Library/Strategy`**: `StrategyAPI`, `StrategyType` (`Download` 1, `NNFX` 2, `DDPG` 3, `Trend` 4 — mirrored to C#). Constructor takes all seven `Parameter` sections in canonical order. `Rule/` = `Download`, `NNFXStrategyAPI` (money/risk base), `TrendStrategyAPI` (adds signals); `Hybrid/DDPG.py` = `DDPGStrategyAPI`, **a sibling of NNFX not a subclass** — it owns its sizing via `Model/Action.py` and deliberately has none of the NNFX stop/scaling machinery. **Parameters resolve through `Ladder.py`, not a folder tree:** `Defaults` in the class body, then overrides merged key by key global → provider → category → ticker → timeframe; most specific wins, a missing override is **not** an error. Overrides live in `inspect_persistent("Overrides")` as sparse deltas stamped with the run that produced them. This retired the 66-file `Library/Parameter` tree, which held only 11 distinct configurations.
- **`Auto` only resolves an indicator's declared ladder** — it reads `SlotAPI.ladder` off the technical indicator in the **leading** slot, so it is meaningful only from slot 2 onward. It has no meaning on a scalar such as `RiskPercentage`. `expand_parameter` **refuses** an `Auto` it cannot resolve, naming the parameter; it used to pass the *string* `"Auto"` through as a value. Switching `Baseline`'s window to `Auto` took Trend from 1 round to 3 (192 → 640 candidates).
- **`Library/System`**: The engine (`SystemAPI`, `SystemType`, `LifecycleAPI`, `RealtimeAPI`, `BacktestingAPI` + `DatasetAPI` tape, `LearningAPI`, `OptimizationAPI`). `Main.py` is the CLI entry point. `Space.py` holds the space algebra (19 functions plus `CandidateAPI`) split out of `Optimization.py`. `OptimizationAPI` is a **sibling of `LearningAPI`** — both orchestrate N backtests over `SplitAPI.walk_forward_folds` and share `_dispatch_()`/`_resolve_()`. **Three decisions, three scopes:** `--fitness` measures one run · `--selection` picks the winner *inside* a fold · `--election` picks one *across* folds (`Frequency` · `Mean` · `Median` · `Last` · `Best`). A fold's model is scored on its **validation** window, never its training window, and the held-out `--testing` pass is **the only unbiased number**. The elected model then runs **twice** — on the held-out window for that number, and over the full range to supply the curve that overlays the walk-forward stitch. **Artifact policy is uniform:** candidates and seeds write nothing; only the elected/full-range run emits, and only for the flags passed. `deliverables(report, export, plot)` scopes them to that run and `quieted(level)` drops both sinks to `Warning` for non-delivering passes.
- **`--continuous` interacts with election and must be reported as such.** Continuity makes folds path-dependent — every fold starts near the previous winner — so `Frequency` election becomes near-tautological because the folds agree by construction. With `--continuous`, `Last` or `Mean` is the honest choice and the run should record which it used.
- **The overfitting budget compounds; it does not reset per stage.** Stages turn a product into a sum (6→2→2→1 is 24 combinations flat, 11 staged) and coarse-to-fine turns a sweep into a funnel, so both cut trials. But stage 3 is conditioned on winners already fitted to the same data, so the effective trial count is the **accumulated total across every stage, round and fold** — which is what a run records, so a deflated metric can be computed against the real number.
- **`Library/Universe`**: `UniverseAPI`, `ProviderAPI`, `CategoryAPI`, `TickerAPI`, `ContractAPI`, `SecurityAPI`, `TimeframeAPI`.
- **`Library/Utility`**: Helper library. **Three persistence tiers, one derived root, no OS-temp dependency:** `inspect_root()` is `<platform data dir>/<App>` where `<App>` is the project root folder name (`inspect_application()`) and is never hardcoded. `inspect_temporary(*folders)` → `<root>/Temp` (pruned by age) · `inspect_persistent(*folders)` → `<root>/Data` (saved runs, weights, overrides — retention never sweeps it) · `inspect_cached(*folders)` → `<root>/Cache` (preload tapes, pruned by **last use** — `_read_cache_` touches `meta.json` on every hit because `PruneAPI.newest` reads the newest *file*, so touching the folder would silently do nothing). `inspect_destination(value, *folders)` turns a flag into a destination. Frame helpers own logging identity: `find_caller_frame`/`find_frame_class`/`find_frame_module`/`find_frame_package`.
- **`Library/Web`**: The Quant Cognition application — the composition root wiring `Library/App/V2` into the deployed Dash app plus the domain pages. **Organized by father route**, one folder per section: `Trading/` · `Research/` (Launch · Result · Backtesting · Optimization · Learning · Research) · `Strategy/` · `Scheduler/` (Base · Entity · Task · Workflow · Run) · `Framework/` (Database · Hierarchy) · `Core/` (Artifact · Status · Catalog, the shared plumbing) · `Service/` (Serve · Tray · Tunnel), with `App.py` and `Launchpad.py` at the root. `Service/` is deliberately **not** re-exported by the package `__init__`, so importing `Library.Web` does not drag in waitress and pystray. `Assets/Callbacks/` holds the four callbacks that speak Scheduler vocabulary (`Cron` · `GateLive` · `GateRuns` · `GateSkip`); everything generic stays in `App/V2`. `Research/Launch.py` declares the CLI surface as `FieldAPI` tuples so one declaration drives the modal, its defaults **and** the command string. A result detail page renders an immutable artifact and therefore **does not poll** — polling re-mounted the grid and discarded sheet tabs and chart zoom. Strictly separated from `Library/Scheduler`; the only sanctioned coupling is the Scheduler page consuming `ManagerAPI`. Footer mottos load from the root `MOTTOS.md` (one quote per `- ` line). **`Setup/Install.py` registers `Service/Tray.py` and `Service/Tunnel.py` by path string into live Scheduler rows** — moving either file means re-running `python -m Setup.Install`. **Desktop and iPad 12.9" are both first-class** — a page is not done until it works on touch as well as mouse. An embedded figure that does not *need* zoom must not capture touch gestures (a Plotly DAG that swallowed one-finger drags made the page unscrollable): set `xaxis.fixedrange`/`yaxis.fixedrange` true, `dragmode` false, `config={"scrollZoom": False, "doubleClick": False, "displayModeBar": False}` — but never `staticPlot: True` when clicks are still wanted, as it kills click events too. Prefer "fits without interaction"; verify at 1024×1366 CSS px, not just desktop.

### C# (`Sources/`)
- **`Sources/Robots`**: Connector cBot (Python bridge via shared memory), `Strategy`, `StrategyAPI` base.
- **`Sources/Indicators`**: Connector indicator, `Indicator` implementations, `IndicatorAPI` base.
- **`Sources/Plugins`**: scaffolded only — `Plugins/Plugin` carries no sources yet.
- **`Sources/Export`**: Build artifacts and deployment exports.

### Testing (`Tests/`)
- **Layout:** mirrors `Library/` (plus `Tests/Auth`, `Tests/Scheduler`, `Tests/Setup`, `Tests/Web`).
- **Naming:** `test_<Subject>.py`. **Style:** same rules and density as the codebase; no docstrings.
- **Exclusions:** `Tests/Bloomberg/` only (live Terminal). `Tests/Spotware/` was excluded until 2026-09-11 because it hung: a stale keyword raised `TypeError` inside a message handler, `_on_message_` swallowed it, the counter never reached its limit and `done.wait(timeout=None)` blocked forever. **A swallowed exception behind an unbounded wait is a hang, not an error** — every streaming test now passes an explicit timeout so a regression fails instead of stalling.
- **`Tests/Golden/`** holds the golden artifacts themselves, not tests. **Two halves, because there are two engines:** `Online/Golden 1-5` are `Simulation` runs of `RealtimeAPI` driven by the Connector cBot in cTrader — their P&L arrives over the wire, so agreement with cTrader there is largely tautological; `Offline/Golden 1-5` are CLI `Backtesting` runs of `BacktestingAPI`, which computes its own fills and fees and is the engine Phase 3 targets. **Compare `Offline/` against cTrader for accuracy; compare either against itself across a change for regression.** Each folder holds `Run.json` · `Parameters.yml` · the five exports. Beside them: `RESIDUALS.md`, the measured record per run, and `Contract.json`, the frozen broker terms — a golden cannot be replayed without it, because `Universe.Contract` is overwritten by every online run. It exists so the runs never have to be repeated; a run left in `<Temp>/Runs` is swept at 30 days.
- **A test that cannot run must skip, never pass.** `if not data: return` reports green having verified nothing; use `pytest.skip`, and let a missing key raise.

### Research (`Research/`)
- **Purpose:** freeze the *method* behind a delivered result so it can be re-run after the framework moves on. One folder per campaign.
- **Contents:** `REPRODUCE.md` (the lock), the training harness and evaluation script at the root, per-phase analyses under `Analysis/`.
- **Not library code.** `SWEEP_*`/`ROBUST_*` environment knobs are allowed here (the no-environment-variable rule governs `Library/`), and the no-comment rule is relaxed only where a measured caveat must travel with the code.
- **Distinct from `Library/Research`** (planned in `PLAN.md` §2.8), the DB-backed run-tracking module.

### Setup (`Setup/`) and `Script/`
- **One boot entry.** Windows Task Scheduler runs only the master orchestrator (`Quant Scheduler` logon task → `pythonw Script/Scheduler.py` → silent tray daemon). The daemon boot-launches service-bearing workflows, supervises services, cron-launches scheduled workflows and advances manual ones.
- **Three standard workflows** (registered by `Setup/Install.py`, owned by `Setup.Auth.ADMIN`): **`Setup`** (manual) = the FK-ordered provisioning DAG (`Enums` · `Auth`→`Logging`→`Scheduler` · `Universe`→`Market`/`Portfolio` · `Indicator`, all `Tolerates=false`; `Logging` precedes `Scheduler` because `Run.LID` references `Logging.Log`); **`Environment`** (daily `0 4 * * *`) = `Cache` → `Retention` → `Update` → `Tunnel` → `Server`; **`Market`** (daily `0 6 * * *`) = `Market.Calendar`.
- **Provisioning tasks** (the `Setup` workflow) are idempotent modules with a uniform `main(database="Quant") -> int` — re-run any task or the whole DAG safely; each also runs standalone (`python -m Setup.Auth`). The `Environment` tasks (`Cache` · `Retention` · `Version` · `Update`) touch no database and take no `database` argument.
- **Shared plumbing is `Setup/Task.py`** — `migrate(db, *datapoints)` and `provision(log, name, work, *, database, detail)`. **`provision` takes the logger and never builds one** (see the logger-identity trap). `Auth`, `Scheduler` and `Indicator` keep bespoke `main()`s and use only `migrate`.
- **The enum block providers declare, they do not run.** `Action` · `Position` · `Strategy` · `Stream` · `System` · `Update` are five-line modules exporting one `*_block()`; `enum_block(name, enumeration)` takes the enumeration itself. `python -m Setup.Enum` is the single entry point. Guard any generator change with the output hash — the committed `Enum.cs` is `36d2f69f2fa39698` (sha256, first 16).
- **Entry point:** `python -m Setup.Install [--database] [--boot]` provisions in-process, registers the workflows, and with `--boot` creates the Windows logon task.
- **`Script/`** holds only essentials: the boot launcher (`Scheduler.py`) plus environment helpers (`System`/`Conda`/`UV` updaters and the `Cache` cleanup each runs first). `Scheduler.py` must stay importable when `Library` is broken — it catches `ImportError` to relaunch under conda, so it may not import `Library` at module level.
